# App audit — 20 Oct 2026

What was checked: every staff screen opened locally (crash test), buttons and labels, date formats, touch/tablet use,
delete safety, database query patterns at scale, job-card status consistency.

## Fixed and live on `main`
| # | Problem | Fix |
|---|---|---|
| 1 | Receiving screen stuck on "Loading…" (a `.catch` that does not exist on the query, so the spinner never cleared) | Rewritten: one joined query, always clears the spinner, client search added |
| 2 | Daily Tasks, My Tasks, alerts panel hung — one database request per job card (hundreds) | One joined query |
| 3 | Job Cards / Ready to Ship / Floor Time silently cut off at 1000 rows, and long id lists in the URL are rejected | Paged reads + chunked id lists (`src/lib/supabaseHelpers.ts`) |
| 4 | My Tasks showed finished and unpaid job cards, and finished jobs as `complete` while everything else uses `completed` | Only `in_progress` shown; one status word everywhere |
| 5 | Add Staff could never work (sent the public key instead of the admin's login token) | Sends the admin's token; clear message if the function is missing |
| 6 | Password reset: false "email sent", reset link could be missed, expired links failed silently | Real error messages; link read before the app starts |
| 7 | Document / photo / template buttons only appeared on mouse hover — invisible on tablets | Always visible on touch screens |
| 8 | Deleting a document, **job card**, photo or template happened with one click | Now asks first |
| 9 | Icon-only buttons had no name (screen readers, and nobody knows what a bare icon does) | Every one has a label / tooltip |
| 10 | Dates in US format (2/26/2027) on some screens | `26 Feb 2027` everywhere |
| 11 | Client Status Board could not be acted on | Resolve / reopen flags with notes |
